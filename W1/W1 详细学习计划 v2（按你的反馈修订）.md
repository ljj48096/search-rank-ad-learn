## 二、D2｜pandas/SQL 快速验证 + sklearn 指标概念与手算

**目标**：用 30 分钟确认基础无死角；把 F1/ROC/AUC 概念学透并手算。

### 上午（2h）
1. **快速验证 3 题（30min）**，各写 1 行能跑通的代码，会就过：
   - merge 左连接：`orders.merge(users, on='user_id', how='left')`
   - 列联表：`pd.crosstab(df['city'], df['is_vip'])`
   - pandas 窗口：`df.sort_values('amt').groupby('city').cumcount()+1`
2. **指标概念（1.5h）**：
   - 混淆矩阵四格：TP/FP/FN/TN
   - 精确率 P = TP/(TP+FP)、召回率 R = TP/(TP+FN)、F1 = 2PR/(P+R)
   - **手算练习（必做）**：10 个样本（预测概率已知），阈值 0.5 和 0.7 各算一次混淆矩阵与 P/R/F1，观察 P/R 一升一降
   - ROC = 阈值从 1 拧到 0 时 TPR（抓对率）vs FPR（误伤率）的曲线；AUC = 曲线下面积 = 随机正样本排在负样本前的概率

### 下午（1.5h）
1. 用 `load_breast_cancer`（sklearn 自带）训练 LR
2. 输出 `confusion_matrix` + `classification_report`
3. **matplotlib 画 ROC 曲线**并标注 AUC
4. **numpy 手写 AUC（排序法）**：按预测分排序，统计正样本排在负样本前的比例，与 `roc_auc_score` 对答案（不一致就查 bug，这是 D 的核心）
5. 对比阈值 0.3/0.5/0.7 下 P/R 变化，写进笔记

### 晚上（0.5h）
- 3 行汇报 + 提示词：【AUC、ROC、F1 到底怎么定义，用比喻讲】【帮我写一段算 F1 的代码】

### 验收标准
- [ ] 手算 F1 与代码输出一致
- [ ] 手写 AUC 与 `roc_auc_score` 一致
- [ ] 能说出 ROC 曲线上一个点代表什么（某阈值下的 TPR 和 FPR）

## 三、D3｜指标收尾：交叉验证 + 速查表 + 面试三句话

**目标**：指标知识一次学透，能讲"为什么不用 accuracy"。

### 上午（2h）
1. 交叉验证（1h）：`cross_val_score` / `StratifiedKFold`；为什么分层（保持各类比例）；和 train_test_split 的本质区别（多次切分 vs 一次）
2. 《指标速查表》定稿（0.5h）：accuracy / precision / recall / F1 / AUC 五项，每项 = 定义|公式|手算例|什么时候看它
3. 面试三句话（0.5h）——写下来背熟：
   - AUC：随机抽一个正样本一个负样本，正样本得分更高的概率，衡量排序能力，不受阈值影响
   - ROC：把阈值从松到紧逐点记录"抓对率 vs 误伤率"画成的曲线，曲线下面积即 AUC
   - F1：精确率和召回率的调和平均，两科都好分数才高，适用于关注正类且类别不平衡的场景

### 下午（1.5h）
1. 升级 D2 脚本：加 `cross_val_score`、对比 LR 不同 C 值（1e-3/1/100）
2. **验证"不平衡下 accuracy 会骗人"**：用 Telco 全量（Churn≈26.5%），全猜"不流失" accuracy 也有 73%，但 AUC/F1 暴露真实水平——把这句话写进笔记

## 四、D4｜Pipeline + LightGBM 深度补课

**目标**：Pipeline 防泄漏原理 + LightGBM 从"只会调包"到"参数含义清楚、会手调"。

### 上午（2h）
1. Pipeline/ColumnTransformer（0.5h）：fit 只在训练折上发生、测试折信息不泄漏——为什么交叉验证必须用 Pipeline
2. **LightGBM 深度补课（1.5h）**：
   - 梯度提升直觉：第 1 棵树直接学，第 2 棵树学"第 1 棵没答对的部分"（残差），依此类推；调参 = 控制"每棵树多激进 + 一共多少棵"
   - 参数表逐行（要求：每个参数能说出"改大/改小会怎样"）：

| 参数 | 作用 | 改大 → | 改小 → |
|---|---|---|---|
| learning_rate | 步长 | 学得慢但稳，需更多树 | 快但易抖 |
| n_estimators | 树数量 | 更充分，配小 lr | 欠拟合 |
| num_leaves | 每棵树叶子数 | 拟合强→易过拟合 | 保守 |
| max_depth | 树深 | 深→更复杂 | 浅→更稳 |
| min_child_samples | 叶子最少样本 | 更保守防过拟合 | 更激进 |
| subsample / colsample_bytree | 行/列采样 | 随机性大→防过拟合 | 更快 |
| reg_alpha / reg_lambda | L1/L2 | 更保守 | 更贴合训练集 |

### 下午（1.5h）
1. 下载 Telco 全量（Kaggle 免申请）；**处理已知坑**：`TotalCharges` 空字符串 → `pd.to_numeric(errors='coerce')` + 填充
2. Pipeline + LR 基线 → `cross_val_score` 记录 AUC
3. LightGBM：默认参数跑一版 → **手调 3 组**（如：A 组 lr=0.05/n_estimators=300；B 组 lr=0.05/num_leaves=63；C 组 lr=0.1/n_estimators=150）→ 每组记录 AUC → 写《调参笔记》：每个改动"观察到什么、为什么"

### 晚上（0.5h）
- 调参笔记定稿 + 3 行汇报 + 提示词：【Pipeline 有什么用】【GBDT 参数怎么调】【LightGBM 和 XGBoost 一句话区别】

### 验收标准
- [ ] 能讲清 Pipeline 防泄漏的原理（fit/transform 只在训练折）
- [ ] 3 组参数实验有完整记录（参数→AUC→解释）
- [ ] 能解释 num_leaves 和 max_depth 分别影响模型什么
